## What you are building

### 1. `h()` — element creation with bindings

```ts
const el = h('div', { class: 'card' },
  h('div', { class: 'card-title' }, () => props.card().title),
  h('div', { class: 'card-meta'  }, () => `${props.card().repo} · ${props.card().agentId}`),
);
```

The single rule that makes this work: **a plain value is set once; a function is a binding.** A
function is wrapped in an effect and updates only its own node when its dependencies change.

- Children: strings, numbers, `Node`s, arrays, and functions. A function child becomes a text node
  (or a node range) that updates in place.
- Props: `class`, `style` (string or object), `id`, arbitrary attributes, `data-*`, `aria-*`. A
  function prop value is a binding, same rule.
- Events: `onClick`, `onInput`, etc. — real `addEventListener`, removed on disposal.
- `ref: (el) => void` to reach the real element.
- Boolean attributes (`disabled`, `checked`) set/remove the attribute rather than writing "false".
- Properties vs attributes: `value` on an input must set the *property*, or a controlled input
  fights the user's typing. Get this right; it is the classic bug in hand-rolled renderers.

Also provide the small binding helpers spec/06 names: `bindClass(el, name, () => boolean)`,
`bindStyle`, `bindAttr`, `bindText`.

**Every binding must be disposed with the element.** An element removed from the DOM whose effect
still runs is a leak that grows for the lifetime of the page. Tie binding lifetime to the owning
`ReactiveScope` (`createScope`), and write a test that proves a removed subtree's effects stop.

### 2. Control flow: `When` and `For`

```ts
When(() => card().blockedReason, reason => h('div', { class: 'blocked' }, reason))
For(cards, card => Card({ card }), card => card.id)
```

- `When` mounts/unmounts a subtree, disposing the old one's effects on unmount.
- **`For` is keyed and must MOVE existing nodes, not rebuild them.** This is the single most
  important property in this dispatch. A card that changes position keeps its DOM node, its focus,
  its scroll position, and any child state. Prove it with a test that holds a reference to a node,
  reorders the list, and asserts the *same node object* is still in the DOM at its new index — not
  merely an equal one.
- `For` must handle: insert, remove, move, and reorder-with-both — and a duplicate key must throw
  with a clear message rather than silently corrupting the mapping.

### 3. Components

A component is a plain function returning `HTMLElement`. There is no base class, no `render()` to
re-run, and no `updateProps()`. Returning `HTMLElement` is honest: it is what the function makes.

Read this, from the framework being replaced (`@flybyme/mesh-ui`), and understand why it is here:

```ts
public getChildren(): BaseComponent<any>[] {
    return this.element.children as unknown as BaseComponent<any>[];
}
```

`element.children` is an `HTMLCollection` of DOM `Element`s. It is not, and cannot become, an array
of `BaseComponent`. Calling any `BaseComponent` method on the result throws at runtime. That single
cast is why **zero `as any` / `as unknown as` / `as never`** is absolute in this codebase.

### 5. Design tokens

One `tokens.css`: colour, spacing, typography, radius as CSS custom properties on `:root`,
redefined under `prefers-color-scheme: dark`, and redefined again under `[data-theme]` so an
explicit choice beats the system. Components reference tokens, never raw colours.

### 6. Accessibility, which is cheap here because the output is real HTML

A clickable thing is a `<button>`. A navigation target is an `<a href>` — a real link, so
middle-click, copy-link-address, and open-in-new-tab work without anyone implementing them. Visible
focus indicators come from the token set.
