## Why this one, and what "done" means

`08-data.md` and `11-example-kanban.md` both show `ctx.api.events.on('card.updated', …)`. Dispatch
#10 deliberately did **not** stub that, because a type implying an SSE client exists would be
believed by the next consumer. So the promise is currently unmet and honestly labelled. This closes
it for real.

**Done means a real app receives a real event over a real HTTP connection**, not that a class
exists. The whole history of this package is that defects appear when something runs: an MCP
transport that 500s on the *second* request, a `.css` import that crashes Node at startup, a base
path that 404s against its own server. None were caught by unit tests. Write the test that opens an
actual server and an actual EventSource-shaped connection.

## What to build

### 1. Server: `GET /api/events?topics=…` returning `text/event-stream`

- **Explicit topic exposure.** A topic is reachable only if listed, exactly like `expose` for
  contracts. No wildcard. An unlisted topic is not an error you can probe your way around — decide
  and document whether it is 403 or silently absent from the stream, and say why.
- **`scope` enforced at fan-out, per subscriber.** This is the security property that matters: two
  subscribers on one topic must receive different events when their scopes differ. Reuse the
  per-org authorization already in this package (`27e6cfb`, `68ac11d`) rather than inventing a
  second rule — a caller scoped to org A must never receive an event about org B, and there must be
  a test that proves exactly that.
- Correct SSE framing: `event:`, `data:`, `id:`, heartbeat comments to keep intermediaries from
  closing an idle stream, and `Last-Event-ID` honoured on reconnect if you keep a buffer (if you do
  not, say so plainly rather than implying replay works).
- Clean teardown: a disconnected client must not leak a broker subscription. Assert it.

### 2. Client: `ctx.api.events`

- `on(topic, handler)` returning an unsubscribe function.
- Wired through the existing `ctx.api` injection seam — do **not** add a second, parallel way for an
  app to reach the backend.
- **Reconnect with backoff and jitter.** A server restart must not leave every browser hammering it
  in lockstep.
- Disposed with the app: unloading an app closes its stream and stops its handlers. The runtime
  already has `registerCleanup`/`trackLeakable`; use them.

### 3. Types

The event payload types must come from the same source the contracts do. If the current codegen
cannot express them, say so precisely rather than widening to `unknown` and calling it done.

## Rules

- **Do not `git commit`.** Leave the work in the working tree.
- **Zero `as any` / `as unknown as` / `as never`.** Absolute in this codebase.
- No new dependencies. Node has everything needed server-side; the browser has `EventSource`. If
  you believe a dependency is unavoidable, stop and explain in your summary instead of adding one.
- **DOM test files need `// @vitest-environment happy-dom` at the top.** Vitest 4 removed
  `environmentMatchGlobs`; without the docblock a file silently has no `document`.
- **Effects are microtask-scheduled** — use `flushSync()` before asserting on the DOM.
- `npm run typecheck` (covers `src` AND `test`) and `npx vitest run` must pass with all 221
  existing tests green.
- Keep the two entry points separate: `.` is exposure (Node), `./runtime` is the browser. A server
  import leaking into the runtime bundle crashed every Node consumer once already.
- Comments explain *why*. House style: `src/exposure/broker.ts`, `src/runtime/dom/h.ts`.
