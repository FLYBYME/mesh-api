================================================================================
THE TASK
================================================================================

Make mesh-api ship compiled output instead of raw TypeScript.

The package already has a `build` script (`tsc`) and produces `dist/`. Nothing
points at it. So every consumer compiles mesh-api's `.ts` sources as part of
their own program under their own tsconfig, and inherits errors from code they
do not own. `skipLibCheck` does not help them, because that skips `.d.ts` and
these are `.ts`.

Three exports exist and all three must keep working — the root (node), `./runtime`
(browser), and `./package.json`:

    "main":  "./src/index.ts",
    "types": "./src/index.ts",
    "exports": {
      ".":         { "types": "./src/index.ts",         "import": "./src/index.ts" },
      "./runtime": { "types": "./src/runtime/index.ts", "import": "./src/runtime/index.ts" },
      "./package.json": "./package.json"
    }

What "done" means:

  - `main`, `types` and `exports` resolve to built `.js` with matching `.d.ts`
  - the build emits declarations (`declaration: true`), and emits them for BOTH
    entry points, root and `./runtime`
  - a `prepare` script so a consumer installing from git gets a build, since this
    package is consumed as `github:FLYBYME/mesh-api` with no npm publish step
  - `dist/` is gitignored and NOT committed
  - the CSS the runtime imports still reaches consumers — `src/runtime/dom/**`
    does `import './x.css'` for real, and `tsc` does not copy CSS. Work out what
    that needs and say what you did.

There is a second, smaller packaging bug in the same family, and the issue names
it: the bin entry `"mesh-api-generate-client": "./src/cli/generate-client.ts"`
points at a raw `.ts` file with no shebang, so `npx mesh-api-generate-client`
fails with `import: not found`. Fix it in this PR — same root cause, same file.

CONSTRAINT — the one that decides which fixes are acceptable:

  Do NOT make mesh-api's own tsconfig stricter to "fix" the 13 errors, and do NOT
  edit the flagged source to satisfy `exactOptionalPropertyTypes`. That is a
  different piece of work and it is not what this issue asks. The point is that a

  makes those 13 disappear for the consumer — it should — that is the fix
